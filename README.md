# SciNode

[简体中文](README.md) | [English](README.en.md)

个人科研可视化 AI 工作流（当前版本 **1.0.0**）：项目分类、任务规划、科研工具、运行摘要、人工审核、版本记录与成果冻结。

## 解决什么问题

科研工作常分散在模型对话、文献工具、分析脚本和本地文件中：讨论出了方案，却看不清执行到哪一步；调整了一个定义，也难以判断哪些下游步骤需要重跑。SciNode 将这些环节连接为可查看、可调整、有审核记录的项目流程：

- **从对话到可执行计划：**助手细化需求，生成节点、连线和模型配置草案；逐项检查变更后再载入项目。
- **从独立工具到可见依赖：**文档、模型、PubMed、Python/R 和 MCP 节点通过输入输出连接，画布显示当前工作位置、结果摘要及失败信息。
- **从生成文本到人工决策：**关键步骤暂停，研究者对照材料批准或退回，决定及意见随运行保存。
- **从一次性输出到可追溯成果：**配置版本、输入来源、实际模型、日志和成果关联到同一次运行；调整后创建重跑分支，审核后冻结成果。

研究者确认研究定义和关键决策，SciNode 负责连接任务、工具、过程与成果。典型路径是：**提出需求 → 规划节点 → 执行工具 → 人工审核 → 导出与冻结**。

## 能做什么

- **科研项目管理：**按专利与方案、文献、临床、数据分析、组学等分类管理项目，查看版本与运行历史。
- **可视化节点配置：**从预设开始或自定义任务，添加、删除及连接节点，选择资料和实际模型，检查配置，查看状态动画与输出摘要。
- **智能对话助手：**规划或修改流程、细化问题、比较草案变更；支持历史会话、归档、中断、附件、本机文件选择，以及项目资料与报错上下文。
- **科研工具接入：**PubMed 文献元数据检索、Word/PDF/文本读取、Python/R 脚本、字段完整性检查、stdio MCP；全局或项目级 Agent 规则与 Skills，可软链接 Codex 来源。
- **审核与交付：**结构化人工确认、Word/PDF/文本导出、成果预览与下载、ZIP 打包、运行分支及成果冻结。PostgreSQL 提取执行代码随仓库提供。

当前应用界面和详细使用指南以中文为主；[英文 README](README.en.md) 提供英文功能与配置说明。

## 运行需要什么

基础服务需要 **Java 21（配置 `JAVA_HOME`）、Maven、Node.js 22+ 与 npm、MySQL、Redis**。MySQL 保存模型、工具连接与知识库等信息，登录账户在私有配置中设置，Redis 用于登录令牌；科研项目、会话、运行与成果保存在本地数据目录。

按所用功能准备额外依赖：

- 大模型助手与科研任务：可调用的模型服务地址、API 密钥和模型；模型列表读取使用 OpenAI 兼容接口。
- 文档、Python 或 R 节点：对应解释器与所需包；文档依赖为 `python-docx`、`pypdf`、`reportlab`，R 示例使用 `jsonlite`。
- PostgreSQL 提取：自己的数据库和只读访问权限，以及 [PostgreSQL Python 依赖](scripts/requirements-postgres.txt)。
- MCP / Codex 来源：相应 MCP 服务，或本机已有的 Codex Skills 与配置。

## 第一次配置 SciNode

新机器先按[本地部署说明 → 从源码配置新环境](本地部署说明.md#从源码配置新环境)操作，完整步骤为：

1. 准备基础服务，克隆仓库，将前后端 `.env.example` 分别复制为私有配置。
2. 填写 MySQL、Redis、个人登录账户和 JWT 密钥；为新数据库导入初始表结构。
3. 安装前端依赖，分别启动后端和前端，打开科研工作台。
4. 在“模型设置”命名服务端口，填写地址与密钥，读取实际模型列表并“测试连接”。
5. 在全局设置选择默认模型与科研规则；按需配置脚本解释器、文档工具、Skills 和 MCP。
6. 从简单流程开始：任务输入 → 科研任务 → 人工确认 → 文档导出 → 成果整理；保存、确认范围后运行。

源码默认 MySQL/Redis 端口为 `3306/6379`；下方已有本机部署使用 `3307/6380`，配置应与自己的服务一致。仓库包含软件与配置示例，本机演示项目、数据库、账号与模型密钥随各自部署保存。

## 节点内对话与长文审阅

在项目画布选中节点，右侧“节点设置”顶部的“与助手一起调整此节点”会打开一个带作用域的对话。助手会看到当前工作区中该节点的实时设置、可用节点和相邻连线（包括尚未保存的调整），可以讨论任务提示词、输入映射、模型和上下游连接；项目名称、其他节点与排布不会被隐式改动。生成草案后先查看逐项对照，再载入到待保存工作区；只读或冻结状态会明确显示，不能载入时仍可继续讨论。

节点、运行成果和附件中的 Markdown 默认以排版后的预览显示，表格、标题、列表和代码块可直接阅读；需要看接口原文时仍可展开“原始内容”。人工确认的“修订对照”提供“连续阅读”和“逐项对照”两种方式，点击“全屏审阅”可在大窗口左右阅读原文与修订稿，长文不再挤在小文本框中。

## 怎样使用和更新

在工作台打开项目，选择节点修改任务和资料，保存后运行；到人工确认节点时检查材料并作出决定。运行记录保留当次需求、配置、模型、输出及审核意见；成果检查后可冻结。模型设置提供实际模型列表和连接测试，全局与项目设置支持 Agent 规则、Skills 和 MCP。

PostgreSQL 流程默认读取本机 `5432/mimiciv` 与 `5433/mimiciii`；修改第一个节点可更换目标库和提取需求。需求与真实表结构交给模型，查询结果保留本机。数据库凭据交由本机 libpq 认证，不填入节点或提示词。提取节点使用的 Python 依赖见 [scripts/requirements-postgres.txt](scripts/requirements-postgres.txt)，部署路径和输入格式见使用指南。

`停止SciNode.command`、`查看SciNode状态.command` 管理本机服务。前端开发在 `frontend/` 执行 `npm run build`，修改文件用项目 ESLint 检查；后端使用 Java 21 与 Maven `test package`。服务命令为 `python3 deploy/local/manage.py start|stop|status`。
